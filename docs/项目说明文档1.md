# HomeOrbit（家环）项目说明文档 1 —— 环境、部署与运行

本文面向当前 workspace 的本机开发与运行交付边界。当前版本已实现三种本地底图、真实步行/驾车路网等时圈、ACS 2023 人口密度和当前选点的五类步行配套分析；AI 对话、学区、安全、房源推荐和公共交通路线未实现。完全断网运行证据仅覆盖本 workspace 已存在并匹配的依赖环境，不代表干净目标机可以直接离线部署。

## 1. 当前功能边界

- 底图：标准地图、交通网图、分析浅色图，共用 `web/public/tiles/bay-area.pmtiles`。交通网图只表达道路/轨道层级，不是实时交通图。
- 通勤：Valhalla `pedestrian`/`auto` 真实路网等时圈；步行与纯驾车支持 15、30、45、60 分钟。
- 配套：当前起点固定 15 分钟步行圈；教育、医疗、日常购物、公园绿地、公共交通站点五类。
- 评分：1,772 个湾区 tract 样本的人口加权相对分；前端按启用分类和权重计算综合指数，改权重不会重新请求空间分析。
- 公共交通路线：控件可见但禁用，状态为“建设中”。公共交通站点只是设施类别。
- 驾车限制：静态纯驾车路网成本，无实时路况、停车搜索、停车可用性或末端步行。
- 失败边界：不生成圆形或其他伪等时圈；单个依赖失败时保留地图、起点和仍可用功能。

项目缓存保持在项目内：

上述 `UV_CACHE_DIR` 与 `npm_config_cache` 只是项目内缓存位置，不等于经 manifest 验证的可移植依赖 bundle。当前 manifest 不包含 Python wheelhouse、uv cache、Node/npm 依赖或 portable production bundle；迁移前必须在联网阶段安装并验证匹配的 `api/.venv`、`web/node_modules`、Node/Python/uv/Docker 环境。当前交付不支持干净、从未安装匹配依赖的完全断网目标机直接部署；未来若另行构建依赖 bundle，必须先纳入 manifest 并重新校验。

## 3. 一次性准备（当前 workspace 重建或联网迁移准备）

以下流程不是日常启动步骤，且要求匹配的 Python/Node 依赖已经安装。先确认目标路径、Docker Desktop、可用磁盘和 5432/8002 现有监听归属；不得覆盖来源不明的服务或数据。Docker image tar、处理后数据、PMTiles 和完整 Valhalla runtime 是已校验的离线资产，但不能替代未打包的 Python/Node 依赖。

### 3.1 已具备匹配依赖时导入缺少的镜像

```powershell
docker image inspect "postgis/postgis:17-3.5" *> $null
if ($LASTEXITCODE -ne 0) {
  docker load -i "E:/HomeOrbit/data/docker-images/postgis-17-3.5.tar"
}

docker image inspect "ghcr.io/valhalla/valhalla:latest" *> $null
if ($LASTEXITCODE -ne 0) {
  docker load -i "E:/HomeOrbit/data/docker-images/valhalla.tar"
}
```

### 3.2 启动 PostGIS 并导入空间数据

```powershell
docker compose -f "E:/HomeOrbit/docker-compose.yml" up -d postgis

cd "E:/HomeOrbit/api"
$env:UV_CACHE_DIR = "E:/HomeOrbit/.uv-cache"
$env:HOMEORBIT_DATABASE_URL = "postgresql://homeorbit:homeorbit_dev@127.0.0.1:5432/homeorbit"
uv run --group data python "../data/scripts/load_spatial_data.py"
```

导入器会事务性核对并 upsert 1,772 个 tract、35,052 条设施和 3 个产品 metadata；重复执行行数不增长。正式数据库当前还应包含 1,772 条 baseline。

### 3.3 一次性构建 Valhalla

```powershell
docker compose -f "E:/HomeOrbit/docker-compose.yml" --profile build run --rm valhalla-build
Get-Content -LiteralPath "E:/HomeOrbit/data/valhalla/.build-complete"
```

`data/scripts/build_valhalla.sh` 只在完整产物不存在时构建；若发现半成品或哈希不一致会安全失败，不会自动删除。成功后必须同时存在非空的 `valhalla.json`、`tiles.tar`、`admin.sqlite`、`tz_world.sqlite` 和 `.build-complete`。再次运行 build 命令会用标记中的 PBF/配置/tiles/辅助库 SHA256 校验完整性后退出。

已知限制：当前镜像的 `valhalla_build_timezones` 在首次 build 阶段可能访问 GitHub 下载 timezone boundary 数据。因此“运行时离线”不等于“首次建图可断网完成”；若迁移到已在联网阶段安装并验证匹配依赖、随后再断网的环境，应直接携带并校验 manifest 中的既有 `data/valhalla/` 产物。日常 Valhalla runtime 不下载或建图。

### 3.4 构建设施评分基准

先启动 PostGIS 和 Valhalla，再执行可恢复构建：

```powershell
docker compose -f "E:/HomeOrbit/docker-compose.yml" up -d postgis valhalla

cd "E:/HomeOrbit/api"
$env:UV_CACHE_DIR = "E:/HomeOrbit/.uv-cache"
$env:HOMEORBIT_DATABASE_URL = "postgresql://homeorbit:homeorbit_dev@127.0.0.1:5432/homeorbit"
$env:HOMEORBIT_VALHALLA_URL = "http://127.0.0.1:8002"
uv run --group data python "../data/scripts/build_facility_baseline.py" --resume
```

完整结果必须为 1,772 条、五类指标均为有限非负数；11 条样本人口权重为零，其中 7 条为水域 tract。完整合法快照复跑应跳过 1,772 条而不重写。

## 4. 日常启动

日常只启动 PostGIS、Valhalla、API 和 Web，不重复导入数据库或构建路由图/基准。

推荐使用项目级统一启动脚本。脚本会先等待 Docker Desktop 就绪，确认 3000/5432/8000/8002 没有既有监听，再启动服务；API/Web 的 PID 和本轮启动的容器会记录在 `tmp/runtime/homeorbit-state.json`。`TEMP`、`TMP`、npm cache 和 uv cache 仅注入本轮子进程并指向 E 盘项目目录，不修改系统环境变量。

```powershell
pwsh -File "E:/HomeOrbit/scripts/Start-HomeOrbit.ps1"
```

启动日志位于 `E:/HomeOrbit/tmp/runtime/logs/`。如只需启动 PostGIS 和 Valhalla，可执行：

```powershell
pwsh -File "E:/HomeOrbit/scripts/Start-HomeOrbit.ps1" -ServicesOnly
```

以下分终端命令保留用于人工排障：

```powershell
docker compose -f "E:/HomeOrbit/docker-compose.yml" up -d postgis valhalla
```

API 终端（保持前台，便于用 `Ctrl+C` 精确停止）：

```powershell
cd "E:/HomeOrbit/api"
$env:UV_CACHE_DIR = "E:/HomeOrbit/.uv-cache"
$env:PYTHONDONTWRITEBYTECODE = "1"
$env:HOMEORBIT_DATABASE_URL = "postgresql://homeorbit:homeorbit_dev@127.0.0.1:5432/homeorbit"
$env:HOMEORBIT_VALHALLA_URL = "http://127.0.0.1:8002"
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Web 终端（保持前台）：

```powershell

```

本机访问 `http://127.0.0.1:3000`。手机/局域网访问前应确认 Windows 防火墙和网络信任边界；不要把开发数据库或 API 暴露到不可信网络。

## 5. API 验证示例

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/gis/health"
Invoke-RestMethod "http://127.0.0.1:8000/gis/config"

Invoke-RestMethod "http://127.0.0.1:8000/gis/isochrone?lng=-122.4194&lat=37.7749&mode=walking&minutes=15"
Invoke-RestMethod "http://127.0.0.1:8000/gis/isochrone?lng=-122.4194&lat=37.7749&mode=driving&minutes=45"

$body = @{ origin = @{ lng = -122.4194; lat = 37.7749 } } | ConvertTo-Json -Depth 3
Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:8000/gis/site-analysis" `
  -ContentType "application/json" `
  -Body $body
```

- `/gis/health`：返回 API、Valhalla、PostGIS、人口文件和 baseline 的组件状态；单项失败时顶层为 `degraded`。
- `/gis/config`：返回可用模式、四档时间、五类设施、数据版本和组件状态。
- `/gis/isochrone`：只接受湾区公共覆盖框内坐标、`walking|driving` 和 15/30/45/60；返回真实 Polygon/MultiPolygon contour。
- `/gis/site-analysis`：请求体只包含起点；设施空间范围固定为 15 分钟步行圈。

## 6. 数据口径和限制

| 项目 | 当前口径 |
|---|---|
| 人口 | ACS 2023 五年数据；1,772 个湾区九县 tract |
| tract 构成 | 1,765 个 Census 制图边界 tract + 7 个官方 TIGERweb 水域 tract |
| 设施 | California OSM 快照；35,052 条；提取时记录 7 个无法构造有效几何的候选 |
| baseline | 1,772 条；11 个零人口权重，含 7 个水域 tract |
| 圈内人口 | tract population × 圈内相交土地面积 / tract 土地面积 |
| 点设施 | 教育、医疗、日常购物、公共交通站点按每千名估算居民计数 |
| 公园 | 圈内去重相交面积（公顷）/每千名估算居民 |
| 相对分 | 1,772 样本的人口加权经验分布；相同值按 `<=` 计入 |

### 6.1 评分 baseline canonical snapshot（只读证据）

`facility_baseline_samples` 全部 1,772 行按 `geoid` 升序，以 `homeorbit-facility-baseline-jsonl-v2` canonical 格式覆盖 `geoid`、`population_weight` 和五类指标；`hash_algorithm=sha256`，SHA256 为 `12e34d9bf137e4b5ade176635a71831806e7aa3537b2a4d30e159d14d4308ebb`。本次 metadata-only upgrade 为 `processed=0 skipped=1772 failures=0`；sample `xmin=853..2627`，`dataset_metadata.key=facility_baseline` 的 metadata `xmin=2727`。两个 xmin 只表示当前数据库证据，不是跨库稳定 ID。独立 live oracle integration test：PASS。

只读复核命令：


人口估算假设 tract 内均匀分布；OSM 设施可能缺失或过时；公共交通站点数量不表示班次、运力或服务质量。估算人口低于 100 时只返回原始供给，不生成分项/综合分。相对分和综合指数不是法规、规划规范或公共服务达标结论。

## 7. 局部降级

- Valhalla 不可用：底图、人口密度、起点和控件保留；通勤等时圈和依赖步行圈的设施分析显示安全中文错误。
- PostGIS 不可用：真实通勤等时圈仍可使用；设施统计和评分不可用。
- 人口 GeoJSON 不可用：人口图层关闭，路由与设施分析不因此被清空。
- 点位越界或无法关联路网：保留标记并提示重新选点。
- 全部设施分类关闭或权重和为零：分项和原始数据保留，综合指数显示“未计算”。

真实断网代理、依赖停止/恢复和界面保留行为以 [验收报告](acceptance/homeorbit-spatial-analysis-report.md) 中主控制器的实测证据为准；单元测试不替代真实运行证据或用户验收。

## 8. 安全停止与归属核对

使用统一启动脚本启动时，优先执行配套停止脚本。它只处理状态文件中记录的 PID，并再次验证进程命令行包含当前项目路径、容器 Compose labels 属于 `homeorbit`；不会删除镜像、volume 或其他项目资源。

```powershell
pwsh -File "E:/HomeOrbit/scripts/Stop-HomeOrbit.ps1"
```

API/Web 以前台命令启动时，在对应终端按 `Ctrl+C`。不要因为某端口存在监听就直接 kill。

处理非本轮启动的监听前，先只读确认 PID 和命令行：

```powershell
$ports = 3000, 5432, 8000, 8002
$listeners = Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
  Where-Object LocalPort -In $ports |
  Sort-Object LocalPort, OwningProcess
$listeners | Format-Table LocalAddress, LocalPort, OwningProcess
$listeners.OwningProcess | Sort-Object -Unique | ForEach-Object {
  Get-CimInstance Win32_Process -Filter "ProcessId = $_" |
    Select-Object ProcessId, Name, CommandLine
}
```

只有命令行明确属于 `E:/HomeOrbit` 且 PID 是本轮记录值时，才可精确执行 `Stop-Process -Id <已记录PID>`。无法确认归属时保持不动并报告。

容器停止前核对 Compose labels：

```powershell
docker inspect "homeorbit-valhalla" --format '{{json .Config.Labels}}'
docker inspect "homeorbit-postgis" --format '{{json .Config.Labels}}'
```

确认 `com.docker.compose.project=homeorbit` 且 service 分别为 `valhalla`/`postgis` 后，按需要精确停止：

```powershell
docker compose -f "E:/HomeOrbit/docker-compose.yml" stop valhalla
# PostGIS 只有在当次明确允许停止时才执行：
docker compose -f "E:/HomeOrbit/docker-compose.yml" stop postgis
```

不要用按端口批量终止、`docker stop $(...)`、`docker compose down -v` 或删除 volume 的方式收尾。
