# 选点吸附与水域显示修复

## 已复现原因

- San Bruno Mountain：选点 `-122.42760492773664, 37.687316698297295`，步行 30 分钟正向请求返回两个不连接的面。Valhalla 实际起算点为 `-122.430374, 37.683942`，`locate` 报告距离 447.9 米，路段为 Ridge Trail（OSM way 42045685），`bridge=false`、`tunnel=false`。关闭轮廓简化仍然断开，说明这处问题主要来自远距离吸附。
- 另一个点 `-122.42401733890435, 37.65813654408923` 默认简化轮廓自交；`generalize=0` 后几何有效。
- Lake Merritt 截图选点 `-122.25266467664434, 37.79701713293075`。接口经纬度、GeoJSON `[lng, lat]`、MapLibre 输入一致，没有发现经纬度互换或重复投影。Valhalla 返回网格近似面，地图原先把分析填色放在水域之上、边线放在最上层，因而湖内显示出错误陆地范围。
- 该湖样本步行路由到 `-122.2610, 37.8085` 返回 2.69 公里、1904.208 秒，`has_ferry=false`。没有发现“游泳”路由模型；该样本不能证明所有湖岸点的通勤时间均准确。

## 修改范围

1. 通勤和在线步行配套分析校验引擎实际吸附点，任一候选点距离超过 100 米则返回 422 `POINT_TOO_FAR_FROM_ROAD`，不返回误导范围。缺少或畸形吸附数据视为上游异常。100 米是交互容差，不是路径连通性证明。
2. 正反向通勤轮廓均使用 `denoise=0, generalize=0`，保留空洞、避免已复现的简化自交。
3. 两个圈的填色、边线和面状设施置于底图同一个不透明水域面下方，地图显示沿底图湖岸遮罩，保留水域面中的陆地岛屿。道路保持在水域之上。
4. 按底图已有 `is_bridge`、`is_tunnel` 标签增强桥梁蓝色实线和隧道紫色虚线。仅表示道路结构，不能作为此模式、此时间内可通行的证据，也不补画推测的跨越连接。
5. 分析错误显示在独立提示条，面板收起后仍可看到并拖动标记重试。

水域此次修复属于**地图显示遮罩**，未对 API 原始轮廓做水域几何差集，也未变更人口、配套统计和既有评分基准。网格轮廓仍是估算，不能声称每个内部点都满足道路导航用时；后续若需要导出精确陆地面或重新核算水域人口，应增加统一水域数据裁剪并同步重算基准。

## 步行提示澄清

用户后续选点 `-122.42864265361318, 37.68749897925241`，普通步行定位、`minimum_reachability=0`、无方式过滤和忽略 access 的诊断查询均返回约 424.3 米外的 Ridge Trail，路段 `pedestrian=true`。未发现该点因步行方式或连通性阈值而被漏掉的更近道路；是否存在未录入步道或可自由穿越地表仍未确认。

100 米是应用的吸附容差，不能解释为禁止现场步行。已将前后端提示改为“现有路网无法确认选点到道路或步道的连接，不代表现场不能通行”，保留校验以避免忽略接入路段及其耗时。当前不支持无路网草地、山坡的自由步行分析。
