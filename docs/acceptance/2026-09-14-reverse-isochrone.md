# 反向可达范围交付与验证

日期：2026-09-14（上海时区）。状态：实现与自动化验证完成，已启动本机服务；真实浏览器视觉和用户验收待完成。

## 本轮范围

增加步行、驾车的反向可达范围，沿用 15/30/45/60 分钟。公交本轮不纳入。

| 可达方向 | 选点含义 | 橙色范围含义 |
|---|---|---|
| 从选点出发（默认） | 起点 | 从这里出发，在指定时间内可达的区域 |
| 到达选点 | 目的地 | 能在指定时间内到达这里的区域 |

应用于上班选址时，可将工作地点设为目的地。方向切换只更新通勤请求；绿色固定 15 分钟步行配套统计仍围绕所选位置计算。

## 实现与依赖

MapControls / MapView → GIS 请求客户端 → `GET /gis/isochrone` → service → ValhallaClient → 本地 Valhalla。

- 请求增加 `direction=outbound|inbound`；省略时为 outbound，兼容原请求。
- 响应回传 direction；原 origin 字段继续表示用户所选参考点，inbound 时该点为目的地。
- inbound 使用引擎 `reverse=true`；两种方向继续保留内部轮廓。
- 非法方向返回 HTTP 400 / INVALID_DIRECTION，中文提示；不会进入路由计算。
- 前端验证响应方向与请求一致，拒绝缺少方向或方向不符的结果；快速切换会取消旧请求，迟到响应不能覆盖最新地图。
- 空选点时，反向模式提示“点击地图设置目的地”；结果面板按实际响应说明方向。

依据：[Valhalla 等时圈官方文档](https://valhalla.github.io/valhalla/api/isochrone/)中 reverse 的定义为向指定位置反向扩展。

## 发现并处理的边界问题

真实旧金山选点（经度 -122.4194、纬度 37.7749）下，反向驾车 30 分钟使用默认 generalize 会产生自交，Shapely 运算报告 TopologyException。

仅针对反向请求设置 `generalize=0`，避免本例的默认简化自交。正向与配套计算参数保持原有口径。这项处理用于保留有效轮廓，不代表消除所有逐点时间误差。

同一点四档反向驾车原始引擎响应测试：

| 分钟 | 默认简化几何有效 | 禁用简化几何有效 | 禁用后原始响应字节 | 单次耗时 |
|---|---|---|---:|---:|
| 15 | 是 | 是 | 338,664 | 0.499 s |
| 30 | 否 | 是 | 481,435 | 1.132 s |
| 45 | 是 | 是 | 735,394 | 1.798 s |
| 60 | 是 | 是 | 968,374 | 2.296 s |

上述耗时为本机单次观测，不是性能保证或百分位统计。反向数据量约为默认简化的五倍，前端性能仍需真实浏览器验收。

## 用户验证

1. 打开并刷新 http://127.0.0.1:3000。
2. 选择“交通网图”，在旧金山市区点击工作地点，选择“驾车 / 30 分钟”。
3. 在“可达方向”切换“从选点出发 / 到达选点”：橙色范围应更新，选点保持原位，结果文案对应当前方向。
4. 检查绿色固定配套圈和评分没有因方向切换而变化。
5. 切换步行及其他时长，再快速切换方向，确认最终图形与已选择的方向一致。
